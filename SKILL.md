# Research Loop

1. Inspect project instructions, active entry points, changes and existing evidence.
   Establish the scientific question, model/loss, data roles, masks/time alignment,
   frozen evaluation, resource authority and stop conditions before launch. Resolve
   missing information when it changes experiment meaning or authorization.
2. Follow [installation](references/installation.md) when the locked runtime is
   unavailable. Select workflow, Group programs, Agent instructions/profiles and
   existing environments through one YAML. Use [operations](references/operations.md)
   for prepare/inspect/start, explicit experiment inputs and control commands.
   Preparation is complete when inspect reports the intended frozen revision,
   profiles, effective permission rules and existing resource declarations.
3. Start only within established model/compute authorization. Retain the run ID,
   status/log/completion paths and supervision owner. Once the detached controller
   owns the work, report those paths; automatic external Codex wakeup is unavailable.
4. Query actual execution facts before intervention. Preserve original operation
   identities, resource ledgers and UNKNOWN outcomes; reconcile uncertainty before
   redispatch. Pause, stop, continue, explicit resume and configuration revisions
   have different admission/settlement semantics specified in operations.
5. Report observed results, publication state, scientific conclusions and limitations
   separately. An applied intervention or finished Group does not establish the
   research goal. Keep private inputs, raw conversations, credentials, runtime
   artifacts and checkpoints outside Git.

For program/session binding, independent Critic contexts and settled-command
recovery, read the [author API](docs/framework-api.md). Shared implementation changes
require a stopped controller and matching prepared snapshot. For trace measurements,
read [measurement guidance](references/operations.md#measurements); historical
measurements do not establish benefits for a new runtime or workload.
