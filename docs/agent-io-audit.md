# Agent input and output audit

Scope: tracked research-loop source and benchmark/integration wrappers. Schemas constrain representation; scientific truth and successful execution still require independent evidence and Review. Raw CLI receipts remain evidence, not controller authority.

Stage, research-execution, Scout, explanation and reduced author-report structures
come from Pydantic v2 models. The same models generate CLI schemas and validate
local responses, including cached acceptance. Extra keys, coercion, nonfinite
numbers and boolean/integer choice confusion are rejected. Context-bound choices
and field omission use derived models; no recursive handwritten schema validator
or reverse compilation of saved schemas remains. External effects, exact source
identity, budgets, accounting and scientific judgments remain separate checks.

## Optional local-MLE patch

`docs/local-mle-agent-output.patch` is a standalone patch against the currently untracked local extension. The extension itself is not included in this PR. It changes only bridge.py/run.py plus focused test fixtures. All work was performed in `/private/tmp/agent-io-local-mle`; the original dirty repository was not modified.

The LocalBridge delegate returns strict `{markdown}`. After the watcher settles, the controller constructs artifacts, IDs, fixed evaluation scope, metrics, evidence and outcome from new in-memory job receipts for this call. The existing frozen-receipt, source, workspace, run/configuration and artifact-effect checks remain in `validate_completed` unchanged and execute before canonical publication. Original agent receipts remain nested under `bridge-call`; unexpected worker failures, unknown job effects and failed receipt publication block parent publication and require reconciliation. Rejected requests prevent a completed outcome even when another job succeeds. No training or evaluation is replayed. Diagnostics remain prose citations instead of invented measured candidates.

Apply from the local extension repository root using `git apply --check /absolute/path/to/docs/local-mle-agent-output.patch`, then `git apply /absolute/path/to/docs/local-mle-agent-output.patch`. The expected base includes the existing untracked `benchmarks/local_mle/{bridge,run}.py` and `tests/test_local_mle_bridge.py`; check first because local edits may have diverged. Verification: Ruff format/check passed all four changed Python files; 29 CPU fixture tests ran successfully with two environment-dependent tests skipped (27 passed). Tests exercised the actual watcher with a simulated training subprocess, receipt tampering rejection, canonical fields/raw receipt separation, inherited requests, budget, failures, mixed successful/rejected requests, unexpected watcher crashes and no replay. No GPU, remote training or private evaluation ran. The patch passed `git apply --check` against the scratch base.

After application, run `PYTHONPATH=tests uv run python -m unittest test_local_mle_agent_output.AgentOutputTests test_local_mle_bridge.BridgeTests` in the local extension checkout. Scientific claims and actual GPU/MPS execution remain outside this CPU contract verification.

Scratch verification was self-contained: copied local extension modules/tests and task core source under `/private/tmp/agent-io-local-mle/edited`; from that directory, `UV_CACHE_DIR=/tmp/research-loop-uv PYTHONPATH=.:tests:src uv run --no-project python -m unittest test_local_mle_agent_output.AgentOutputTests test_local_mle_bridge.BridgeTests`. This used simulated trainer/evaluator fixtures and did not import the original dirty extension.

Cactus and Meta benchmark watcher callbacks capture unexpected worker failures and block canonical parent completion, including when a completed job/pair is retained in memory. Focused guard regressions run the actual wrapper/watch boundary with simulated delegates; errors require reconciliation and never trigger a retry. Benchmark prompts now explicitly request report-only output rather than showing obsolete measurement-copy examples.

## Constraint boundaries

Every model-facing prompt/schema is persisted at the actual CLI invocation. Canonical Plan consumers (continuation, resume submission, dashboard and explanation) verify the accepted call, unchanged raw receipt and exact controller reconstruction; they label controller-owned fields separately. The core also persists its expected internal schema for custom adapters; adapter child directories hold their reduced model schema. Model-authored source IDs, review targets, candidate choices and experiment designs remain semantic bindings, not generated authority. Repeating an evaluation ID in a generic measurement is constrained to frozen definitions; adapters with a trusted backend construct it without asking the model.

Prompt instructions alone cannot guarantee arbitrary scientific claims, file correctness or cross-field consistency. Dynamic schema constrains known choices. Runtime validates relationships: published-reference membership, exact Review coverage, source/version identity, finite complete measurements and side effects. Unaccepted read-only output parameter errors return to the same stage with retained rejection evidence and the original budgets. Pipeline failures and source/effect/identity/accounting checks remain blocking; changing response shape must not replay Execute. Completed historical artifacts are retained; this change does not rewrite or automatically accept the blocked online iteration 0026.

No dataset/checkpoint validation scan or training-startup check was introduced. All checks here concern small agent/control metadata at call/result boundaries. Verification uses CPU fixture backends and actual local Study/Git/CLI paths; no new scientific measurement or live model/GPU success is claimed.

Benchmark follow-up: Cactus and Meta authors return only markdown; outcome is entirely controller-owned. Alive watchers, controller remote errors and uncompleted submitted jobs block canonical publication and require reconciliation. Bounded tests cover retained successful results with live workers/errors. Meta uses the core's parameter feedback rather than a separate cardinality-error retry wrapper. Review correction consumes the existing call/time and token budgets; Execute is never replayed.

Canonical Plan views: `plan_provenance.accepted_plan_response` verifies accepted canonical references against the original completed/raw response and the selected proposal base in published controller state. Canonical files must exactly equal that reconstruction. Explanation sources label canonical Plan output as controller-owned; dashboard agent panels retain the raw model response without a base field. Canonical/raw/selection tampering is rejected by focused fixtures. Study version 3 is required before controller state changes; older Study records remain preserved and require a newly initialized Study for execution.
